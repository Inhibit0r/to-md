# to-md

Скилл ручной: документы в глобальной маршрутной карте уже принадлежат `document-skills:*`, и модель-инвокед конвертор создал бы вторую дорогу к тем же файлам. Граница простая — **в md идёт конвертор, из md в документ идут `document-skills`**.

Материал приходит **черновиком**: у медиа модель путает имена собственные (**ослышки**), у снимков часть текста нечитаема. Скилл доводит его до чистовика.

Вход — путь или ссылка из просьбы. Не назван → `./in`.

Выход зависит от того, есть ли у материала второй этап:

- **документы** (pdf, docx, xlsx, rtf, epub, csv…) — итог сразу: md ложится **рядом с исходником**, `Договор.pdf` → `Договор.md`. Папка `out/` для них не создаётся. Рядом уже лежит чужой md с тем же именем → он не трогается, выход получает имя `Договор-pdf.md`;
- **медиа и фото** — черновик и чистовик: пофайловые md в `./out/raw/`, summary и сводный `задачи.md` в `./out`.

## 0. Среда

Определи абсолютный путь к корню установленного плагина по пути **этого** `SKILL.md`: от `skills/convert/SKILL.md` поднимись на три уровня. В Claude Code можно взять подставленный `${CLAUDE_PLUGIN_ROOT}`, если там есть `scripts/to_md.py`. В Codex бери путь навыка из каталога текущей сессии. Ниже `ROOT` — этот абсолютный путь. Запускай команды из рабочей папки материала, а не из каталога плагина.

```bash
python "${ROOT}/scripts/to_md.py" --doctor
```

На macOS и Linux интерпретатор называется `python3` — если `python` не нашёлся, повтори с ним.

`ready: false` → скажи пользователю, чего не хватает (по полям `python_ok`, `whisper`, `anydoc`). Предложи ему вызвать `$to-md:setup` в Codex или `/to-md:setup` в Claude Code и остановись.

Планируется забор с Plaud и в ответе `plaud_token` не `true` → предупреди пользователя заранее: `false` — токен протух (загрузчик сам попробует обновить через CLI и, если refresh мёртв, упадёт с подсказкой), `null` — логина ещё не было, нужен `plaud login`.

Готово, когда: в ответе `--doctor` `ready: true`.

## 1. Черновик

Записи с диктофона Plaud («забери с плауда», «последний созвон») сначала едут в `in/`:

```bash
"${VENV_PYTHON}" "${ROOT}/scripts/fetch_plaud.py" --latest 1 --out in
```

`VENV_PYTHON` — путь `venv` из доктора. Если поле пустое, используй тот же Python, которым запустил доктора.

Ссылка (YouTube, Instagram, TikTok, VK — всё, что знает yt-dlp) идёт первым аргументом вместо папки: скрипт сам кладёт файл в `in/` и обрабатывает только его. Язык ролика чаще не русский — не забудь `--lang`:

```bash
python "${ROOT}/scripts/to_md.py" "<url>" --out out --lang en --json
```

Скрипт упал одной строкой на stderr → причина там: нет yt-dlp, приватное видео, сеть. Если не хватает yt-dlp, предложи команду настройки из шага 0. Сеть закрыта → прокси в `TO_MD_PROXY`, загрузчик подхватывает её сам.

Папка или файл — один прогон делает всю детерминированную работу:

```bash
python "${ROOT}/scripts/to_md.py" in --out out --json
```

Ручки: `--lang en`; `--gap 1.2`; `--device cpu`; `--vad False` — если в готовой расшифровке подозрение на выпавшие куски. `--hotwords 'Имя, Топоним.'` — **только для чистой записи одного голоса** (лекция, диктовка): на тихой или групповой записи whisper подменяет неразборчивую речь строкой подсказки; точка в конце обязательна, иначе транскрипт придёт без пунктуации.

Медиа считается примерно в 25 раз быстрее реального времени на GPU и заметно медленнее на процессоре; timeout ставь от 600000.

Файл вышел кривой → сотри его md и повтори прогон, переделается ровно он: у медиа и фото запись реестра жива, только пока md лежит в `out/raw/`; у документа прогон переделывает md, если его нет рядом или исходник правили позже.

Готово, когда: JSON получен. В нём `converted` — сделанное (у документа `md` — путь рядом с исходником, у медиа — относительно `out/`), `skipped` — пропущенное с причиной, `cached` — то, что уже сделано, `text` — файлы, которые читаются напрямую, `photos` — план на снимки.

## 2. Фото: веер

`photos.batches` пуст → шаг пропускается целиком, иди к шагу 5.

`photos.mode` говорит, как раздать работу:

| mode | Как |
|---|---|
| `inline` | снимков меньше пяти — читаешь сам, спавн дороже, чем экономит |
| `parallel` | все батчи одним сообщением, субагенты идут одновременно |
| `waves` | по `photos.wave_size` батчей за раз, следующая волна после предыдущей |

Если текущий клиент и пользователь разрешают субагентов, передай каждому батч и этот промт. В Claude Code для первого прохода используй Sonnet 5. При отсутствии разрешения или инструмента обработай батчи последовательно сам.

> Прочитай контракт `<ROOT>/skills/convert/photo-contract.md` и распознай по нему снимки: `<пути из батча>`. Пиши файлы в `out/raw/`, в ответ верни по три строки на снимок, как требует контракт.

В ветке `inline` контракт читаешь ты сам и работаешь по нему же.

Субагент не вернул файл → снимок идёт в отчёт пользователю, реестр записи не заводит: следующий прогон переделает.

Готово, когда: на каждый снимок из `photos.batches` в `out/raw/` лежит md, либо он назван в списке несделанных.

## 3. Эскалация

```bash
python "${ROOT}/scripts/to_md.py" --escalate out/raw
```

Список непустой → сделай второй проход для каждого файла. В Claude Code при разрешённой делегации используй Opus. Иначе перечитай снимок сам.

> Прочитай контракт `<ROOT>/skills/convert/photo-contract.md`. Снимок `<путь к исходнику>` распознан с потерями, текущий результат — `<путь к md>`. Перечитай снимок целиком, кадрируй и увеличивай подозрительные места, перепиши файл заново по контракту. Метки `[неразборчиво]` оставляй только там, где текст действительно не читается.

Метки после второго прохода остаются → снимок действительно нечитаем. Это честный результат, третьего прохода нет.

Готово, когда: `--escalate` отработал, и по каждому файлу из его списка прошёл второй проход.

## 4. Склейка

```bash
python "${ROOT}/scripts/to_md.py" --collect out --in "<исходный файл или папка>"
```

Сводный `out/задачи.md` пересобирается целиком на каждом прогоне. Правки вносятся в пофайловые в `out/raw/` — в сводном они не переживут следующий прогон.

Готово, когда: напечатанное число совпадает с числом фото-md в `out/raw/`.

## 5. Медиа: сведение alt-прогона

Только для записей, у которых в `converted` есть `suspect`. Детектор пометил петли, титры-артефакты, провалы и дыры — и скрипт сам сделал второй прогон другим профилем: рядом лежит `raw/<имя>-alt.md` (без VAD и без hotwords), в реестр он не входит.

Открой оба файла и сведи лучшее в основной md: куски, названные в баннере `> Подозрение на потери`, замени текстом alt на тех же таймкодах; живой текст основного не трогай. После сведения удали баннер и файл `-alt.md`. Alt в том же месте тоже кривой → оставь честную дыру: третьего прогона нет, как и у фото.

Готово, когда: в `out/raw/` нет файлов `-alt.md`, а в основных md — баннеров.

## 6. Медиа: чистовик и summary

Для файлов с `kind: media` в `converted`. Если прошлый прогон оборвался после записи raw, также доделай сводку для записи из `cached`, если её raw найден и ни одна готовая сводка ещё на него не ссылается.

В Claude Code при разрешённой делегации выбери Sonnet 5 для raw короче 20 000 символов, Opus для более длинного. Указанная пользователем модель имеет приоритет. В Codex или без субагентов выполни контракт сам:

> Прочитай `<ROOT>/skills/convert/summary-contract.md` и разбери по нему `<путь к out/raw/файлу.md>`.

Дальше запиши:

- замены из блока 2 применить к `out/raw/<имя>.md` построчно;
- в его фронтматтер дописать `type: <созвон|лекция|заметка|документ>`;
- summary записать в `out/<Заголовок ДД-ММ>.md`: заголовок, строка «дата · длительность · тип», разделы шаблона, последней строкой ссылка `[Полная расшифровка](raw/<имя>.md)`. YAML в summary не ставить — файл вставляют в редакторы. Имя записи это только дата и время → заголовком берётся тип: `Созвон 07-08.md`.

Готово, когда: на каждый медиафайл из `converted` есть summary в `out/`, и ни одного пункта без якоря в нём нет.

## 7. Отчёт

Путь к результату · что сделано и что пропущено с причиной · снимки, где остались метки `[неразборчиво]` · для медиа: тип, длительность, 3–5 пунктов по существу, сколько замен внесено · подозрения детектора и что сведено из alt · «под вопросом», если непусто.
