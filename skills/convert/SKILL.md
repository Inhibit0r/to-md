# to-md

Скилл ручной: документы в глобальной маршрутной карте уже принадлежат `document-skills:*`, и модель-инвокед конвертор создал бы вторую дорогу к тем же файлам. Граница простая — **в md идёт конвертор, из md в документ идут `document-skills`**.

Материал приходит **черновиком**: у медиа модель путает имена собственные (**ослышки**), у снимков часть текста нечитаема. Скилл доводит его до чистовика.

Вход — путь из просьбы. Не назван → `./in`. Выход — `./out`, пофайловые md в `./out/raw/`.

## 0. Среда

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/to_md.py" --doctor --data "${CLAUDE_PLUGIN_DATA}"
```

На macOS и Linux интерпретатор называется `python3` — если `python` не нашёлся, повтори с ним.

`ready: false` → скажи пользователю, чего не хватает (по полям `python_ok`, `whisper`, `anydoc`), отправь к `/to-md:setup` и остановись.

Готово, когда: в ответе `--doctor` `ready: true`.

## 1. Черновик

Записи с диктофона Plaud («забери с плауда», «последний созвон») сначала едут в `in/`:

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/fetch_plaud.py" --latest 1 --out in
```

Затем один прогон делает всю детерминированную работу:

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/to_md.py" in --out out --data "${CLAUDE_PLUGIN_DATA}" --json
```

Ручки: `--hotwords 'Имя, Топоним.'` — имена собственные из контекста разговора, **точка в конце обязательна**, иначе транскрипт придёт без пунктуации; `--lang en`; `--gap 1.2`; `--device cpu`.

Медиа считается примерно в 25 раз быстрее реального времени на GPU и заметно медленнее на процессоре; timeout ставь от 600000.

Готово, когда: JSON получен. В нём `converted` — сделанное, `skipped` — пропущенное с причиной, `cached` — то, что уже в реестре, `text` — файлы, которые читаются напрямую, `photos` — план на снимки.

## 2. Фото: веер

`photos.batches` пуст → шаг пропускается целиком, иди к шагу 5.

`photos.mode` говорит, как раздать работу:

| mode | Как |
|---|---|
| `inline` | снимков меньше пяти — читаешь сам, спавн дороже, чем экономит |
| `parallel` | все батчи одним сообщением, субагенты идут одновременно |
| `waves` | по `photos.wave_size` батчей за раз, следующая волна после предыдущей |

Каждому субагенту (`Agent`, `subagent_type: general-purpose`, `model: sonnet`) — свой батч и этот промт:

> Прочитай контракт `${CLAUDE_PLUGIN_ROOT}/skills/convert/photo-contract.md` и распознай по нему снимки: `<пути из батча>`. Пиши файлы в `out/raw/`, в ответ верни по три строки на снимок, как требует контракт.

В ветке `inline` контракт читаешь ты сам и работаешь по нему же.

Первый проход — **Sonnet 5** на все снимки: у него высокое разрешение, 2576 px по длинной стороне. Haiku в схеме не участвует — он в старом тире 1568 px, и это ровно та разница, которая решает на почерке и на снимке монитора.

Субагент не вернул файл → снимок идёт в отчёт пользователю, реестр записи не заводит: следующий прогон переделает.

Готово, когда: на каждый снимок из `photos.batches` в `out/raw/` лежит md, либо он назван в списке несделанных.

## 3. Эскалация

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/to_md.py" --escalate out/raw
```

Список непустой → второй проход **автоматически, без вопроса пользователю**: обнаружение меток и есть решение о перепроверке. Субагент (`Agent`, `subagent_type: general-purpose`, `model: opus`) на каждый файл из списка:

> Прочитай контракт `${CLAUDE_PLUGIN_ROOT}/skills/convert/photo-contract.md`. Снимок `<путь к исходнику>` распознан с потерями, текущий результат — `<путь к md>`. Перечитай снимок целиком, кадрируй и увеличивай подозрительные места, перепиши файл заново по контракту. Метки `[неразборчиво]` оставляй только там, где текст действительно не читается.

Метки после второго прохода остаются → снимок действительно нечитаем. Это честный результат, третьего прохода нет.

Готово, когда: `--escalate` отработал, и по каждому файлу из его списка прошёл второй проход.

## 4. Склейка

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/to_md.py" --collect out --in in
```

Сводный `out/задачи.md` пересобирается целиком на каждом прогоне. Правки вносятся в пофайловые в `out/raw/` — в сводном они не переживут следующий прогон.

Готово, когда: напечатанное число совпадает с числом фото-md в `out/raw/`.

## 5. Медиа: чистовик и summary

Только для файлов, у которых `kind: media` в `converted`. Документы и фото этот шаг не проходят.

Посчитай объём raw в символах и выбери модель: **< 20 000 → Sonnet 5**, **≥ 20 000 → Opus**. Слова пользователя («на опусе», «на сонете») сильнее порога.

Субагенту (`Agent`, `subagent_type: general-purpose`, синхронно, `model` по порогу):

> Прочитай `${CLAUDE_PLUGIN_ROOT}/skills/convert/summary-contract.md` и разбери по нему `<путь к out/raw/файлу.md>`.

Дальше запиши:

- замены из блока 2 применить к `out/raw/<имя>.md` построчно;
- в его фронтматтер дописать `type: <созвон|лекция|заметка|документ>`;
- summary записать в `out/<Заголовок ДД-ММ>.md`: заголовок, строка «дата · длительность · тип», разделы шаблона, последней строкой ссылка `[Полная расшифровка](raw/<имя>.md)`. YAML в summary не ставить — файл вставляют в редакторы. Имя записи это только дата и время → заголовком берётся тип: `Созвон 07-08.md`.

Готово, когда: на каждый медиафайл из `converted` есть summary в `out/`, и ни одного пункта без якоря в нём нет.

## 6. Отчёт

Путь к результату · что сделано и что пропущено с причиной · снимки, где остались метки `[неразборчиво]` · для медиа: тип, длительность, 3–5 пунктов по существу, сколько замен внесено · «под вопросом», если непусто.
