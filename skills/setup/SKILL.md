# Установка to-md

to-md держит собственный интерпретатор в `<data>/venv` и работает только им. Системный python нужен ровно на то, чтобы запустить установку: его версия и состояние роли не играют, лишь бы скрипт стартовал. Ничего в системный python не ставится.

## 1. Что за машина

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/to_md.py" --doctor --data "${CLAUDE_PLUGIN_DATA}"
```

`python` не нашёлся → повтори с `python3`. Не нашёлся ни один → ставить нечем, скажи об этом и остановись.

Готово, когда: JSON получен и ты знаешь `os`, `arch`, `venv`, `whisper`, `anydoc`, `plaud`, `ytdlp`, `nvidia`, `data`, `weights`, `ready`.

## 2. План под эту машину

`ready: true` → ставить нечего, иди к шагу 4.

`ready: false` → покажи пользователю, что произойдёт, и **дождись согласия**:

- в `<data>/venv` создаётся отдельный python 3.12, который uv скачивает сам;
- в него ставятся `whisper-ctranslate2`, `firecrawl-anydoc`, `requests`, `yt-dlp` (ссылки на YouTube, Instagram и прочие медиаресурсы);
- системный python и его пакеты не трогаются;
- если uv нет, он ставится официальным инсталлером astral.sh в `~/.local/bin`.

`nvidia: true` → предупреди, что следом понадобятся `nvidia-cublas-cu12` и `nvidia-cudnn-cu12` (шаг 3). На `os: Darwin` они не нужны: у CTranslate2 нет Metal, считает процессор.

Готово, когда: пользователь увидел список и согласился.

## 3. Установка

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/to_md.py" --bootstrap --data "${CLAUDE_PLUGIN_DATA}"
```

Одна команда делает всё и заканчивает тем, что печатает доктора уже из нового окружения.

`nvidia: true` → добери туда драйверные пакеты, `<venv>` берётся из поля `venv`:

```bash
uv pip install --python "<venv>" nvidia-cublas-cu12 nvidia-cudnn-cu12
```

Не сработало → покажи вывод целиком и остановись. Не ставь эти пакеты в системный python: ровно от этого venv и защищает, а на managed-интерпретаторе (PEP 668, штатное состояние для python из Homebrew и большинства дистрибутивов Linux) установка всё равно откажет.

`ytdlp: false` при `ready: true` — окружение собрано до появления загрузчика ссылок: добери `yt-dlp` той же командой `uv pip install`, на Windows без venv — `pip install yt-dlp`.

YouTube без JS-рантайма yt-dlp объявил устаревшим: пока работает, но часть форматов может пропасть. Ссылки на YouTube ходят часто → предложи поставить `deno` (winget / brew), yt-dlp найдёт его на PATH сам. ffmpeg не нужен: дорожка качается как есть.

Готово, когда: доктор даёт `ready: true`.

## 4. Веса

Отдельный вопрос, потому что это полтора гигабайта. Согласился:

```bash
"<venv>" -c "from faster_whisper.utils import download_model; print(download_model('large-v3-turbo', output_dir=r'<data>/models/large-v3-turbo'))"
```

`<venv>` и `<data>` — одноимённые поля из доктора. Именно `venv`, а не текущий `python`: `faster_whisper` живёт только в окружении to-md.

Полтора гигабайта тянутся не мгновенно: долгая команда — не признак зависания, судить о провале можно только по ошибке или по остановке роста `<data>/models/large-v3-turbo`.

Загрузка виснет на нуле байт → это xet-загрузчик HuggingFace: поставь `HF_HUB_DISABLE_XET=1`, а если хаб недоступен — прокси в `TO_MD_PROXY`, конвертор подхватывает её сам.

Отказался → веса скачаются при первом прогоне, скажи об этом.

Готово, когда: доктор даёт `weights: true`, либо пользователь сознательно отложил загрузку.
